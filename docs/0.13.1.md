# 0.13.1：覆盖链接下的右键图片采集

桌面服务 0.13.1；推荐采集扩展 0.6.2。发布附件追加了扩展 0.6.2，原安装程序与完整软件包保持原样（仍附带扩展 0.6.1）。

扩展 0.6.2 修复安装后已打开的页面缺少监听，以及网页拦截 contextmenu 导致右键位置丢失的问题，详见 [0.6.2 说明](extension-0.6.2.md)。

旧版“保存图片到拾素材”仅注册在浏览器的 image 右键上下文。Pinterest 一类卡片把链接覆盖在图片上时，浏览器识别为 link，菜单就不会出现。

## 修复

- “保存此处图片到拾素材”同时支持图片、链接和页面右键上下文。
- 扩展在隔离脚本中记录最近一次右键的位置与页面地址，选择采集后才解析该位置覆盖的图片或背景图。
- 搜索限于点击位置和附近容器，并要求图片覆盖点击点；空白区域会提示未找到图片，不自动采集旁边的卡片。
- 支持 HTTP/HTTPS iframe 内的右键位置与原框架读取。
- 覆盖链接场景使用页面提供的 srcset、原图属性等候选，保留签名参数；普通 image 上下文保留原来的直接图片地址行为。
- 页面已跳转、位置过期、扩展站点访问受限等情况给出明确提示。原右键菜单照常显示。

内容脚本只在内存记录最近一次右键的坐标、时间与页面地址。没有新增浏览器权限，仍使用已有的 HTTP/HTTPS 网站访问权限；选择采集前不发送网页图片或连接密钥。

## 验证与限制

追加修复后 173 项测试通过。独立 Edge 配置和真实扩展验证了覆盖链接下的兄弟图片、响应式大图候选、签名参数、背景图、跨源 iframe 和空白区域拒绝；实际入库原件哈希一致，页面运行错误为零。

界面回归通过真实右键事件记录点击位置，再调用同一个菜单处理函数；没有自动点击浏览器原生菜单。测试入口 `node tools/context-capture-browser-check.mjs` 使用临时扩展入口暴露该回调，生产扩展没有测试接口。

用户报告页面为 Pinterest 首页。当前会话连接用户浏览器连续超时，尚未完成已登录 Pinterest 首页实测。该修复覆盖截图所示的 link 上下文问题，不能据此承诺所有 Pinterest 图片、登录限制或其他网站都兼容。

## 更新后操作

1. 单独下载并解压扩展 0.6.2；在 Chrome / Edge 扩展管理页加载新目录，或替换原目录后点击“重新加载”。
2. 确认拾素材扩展允许访问 Pinterest。
3. 刷新已经打开的 Pinterest 页面，使新的右键位置脚本生效。
4. 在图片中间右键，选择“保存此处图片到拾素材”；多菜单时可能收在拾素材子菜单里。

桌面端已有的采集协议继续兼容；安装 0.13.1 可从软件中下载新版扩展。保留原件 ZIP 导出、图片转换和原有素材库。
