# 拾素材监控文件夹管理接口（0.10.0）

这些是拾素材自己的管理接口，不是 Eagle API 兼容接口。基址默认 `http://127.0.0.1:41600`，只在本机监听。所有接口都需要 `X-Assetnest-Key`；修改时应同时传 `X-Assetnest-Library`，避免把操作提交到切换后的库。JSON 请求使用 `Content-Type: application/json`。跨站及浏览器扩展来源禁止管理监控目录；从客户端设置操作即可，无需额外调用接口。

| 方法 | 路径 | 请求与结果 |
|---|---|---|
| GET | `/api/watch-folders` | 返回 `rules`、正在扫描的 `current`、`extensions`、`maxBytes` 和可见错误 `lastError` |
| POST | `/api/watch-folders` | `{directory,folderId?,tags?:[],recursive?:false,importExisting?:false}`；添加后返回 201 和状态 |
| PATCH | `/api/watch-folders/:id` | `{paused:true或false}`；暂停或继续 |
| DELETE | `/api/watch-folders/:id` | `{}`；停止并移除规则，保留源文件和已入库素材 |
| POST | `/api/watch-folders/:id/retry` | `{}`；失败项变为等待，暂停规则须继续后处理 |

规则包含 `id`、`directory`、`folder_id`、`tags`、`recursive`、`paused`、`initialized`、`importExisting`、`last_scan`、`error`、`counts`、`recent`。`recent` 最多 20 条，含相对路径、状态、错误和已入库素材 ID；同一个来源路径保留最近版本的状态。

状态包括 `baseline`（初始已有文件，不入库）、`waiting`、`importing`、`imported`、`duplicate`、`failed`、`skipped`。`initialized` 为 false 时尚未完成初始目录扫描。接口成功仅代表规则已保存，实际原文件提交结果以处理记录为准。

错误返回 `{error}`：401 为密钥错误，403 为来源不允许，404 为规则不存在，409 为请求对应的素材库已变化，400 为目录/配置不合法。添加规则在维护任务期间可能暂不可用；暂停、继续、移除和失败重试仍可管理。
